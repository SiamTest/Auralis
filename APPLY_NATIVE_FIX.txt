Complete Auralis project — v0.1.7+8

This is the FULL project with files at the ZIP root. It includes embedded music covers, channel photos, saved Library sorting, selected-channel indexing, original-quality streaming, TDLib caching, the native shutdown fix and stable-release publisher repair.

1. Extract this ZIP.
2. Upload all extracted files/folders into the SiamTest/Auralis repository root, including .github, lib, windows, test, tool, third_party, native, docs, LICENSE, pubspec.yaml and pubspec.lock. Do not upload only the ZIP or a few changed files.
3. Commit to main. The workflow checks, builds, tests and packages the Windows app, then publishes stable v0.1.7 after verifying uploaded asset checksums. Rerunning an old commit cannot apply these changes. Existing tags and published releases are never moved/overwritten.

Covers: displayed music first tries Telegram's supplied thumbnail; if missing/unavailable, reads embedded art from MP3 (ID3v2), FLAC and M4A/MP4 metadata ranges. Tiny Telegram previews display while loading. Metadata is bounded to 4 MiB, parsed off the UI isolate, limited to two concurrent jobs and 64 cached cover results. A playing file's download offset is never changed for artwork; it uses buffered bytes and retries on progress. Files without pictures, unsupported containers or invalid/oversized art keep a preview/placeholder. No online artwork search or quality conversion is used. Refresh retries old failures.

Sorting: click Sort Library beside the Library heading. Choose newest/oldest Telegram post, title, artist or shortest duration. Your selection is saved between launches. Sorting respects the search filter and does not change an existing queue/playing item.

Telegram selection: only channels appear. Select one or more to combine every older audio/document page in Library. Channel selections persist. Local music importing/playback is removed; old paths are ignored without deleting files.

Build/release: this version is 0.1.7+8 and stable tag v0.1.7. Later updates need a new stable version, e.g. 0.1.8+9. The stable native-builder/image TDLib cache key is unchanged, so these Dart/UI edits do not force a TDLib rebuild. Cache migration succeeded in GitHub run 39264104723. Publishing resolves drafts by numeric ID, preserving the fix for its earlier HTTP 404. The existing v0.1.3 tag stays intact; no old tag/draft deletion is needed.
